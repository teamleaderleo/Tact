# Tact atelier

**The living design-memory surface.**

Tact is allowed to be messy at capture time and precise at decision time.

This page gives the repository a small number of distinct jobs without turning it into a filing system.

## The loop

```text
notice
-> capture
-> annotate
-> imitate / alter when useful
-> apply to real work
-> name what happened
-> promote only what keeps surviving
```

The repository should make it easy to enter at any point in that loop.

## Surfaces

### [`RESERVOIR.md`](RESERVOIR.md) — things worth seeing again

Low-friction source reservoir: references, screenshots, products, physical objects, typography, motion, games, diagrams, weird interfaces, and anything else that catches the eye.

Capture first. A one-line “what caught me” is enough.

### [`studies/`](studies/) — understand by making

Small recreations, variations, visual drills, interaction sketches, measurements, and implementation studies.

Use this when the hands can answer a question prose cannot.

### [`case-studies/`](case-studies/) — apply judgment to reality

Real products and workflows, concrete current behavior, alternatives, use notes, and decisions.

This is the strongest evidence in Tact because the work has an actual job to do.

### [`patterns/`](patterns/) — reusable moves that earned names

Promote only after several cases support the move and its failure boundary is understood.

Patterns are optional. The repository does not need a pattern for everything.

### [`SIGNATURE.md`](SIGNATURE.md) — choices Leo keeps making

A slowly changing record of recurring preferences across unrelated work.

The signature is discovered from the trail. It is not a visual theme imposed on every project.

### [`SHITLIST.md`](SHITLIST.md) — precise failures

Keep the raw “this is bullshit” reaction, then identify the user cost, design decision, and smallest stronger alternative.

Negative taste becomes much more useful once it can name the defect.

### [`PROJECT-BRIEF.md`](PROJECT-BRIEF.md) — use Tact on the next thing

A reusable prompt/working brief for pointing a new project or agent at Tact without asking it to blindly copy the repository's preferences.

### [`APPLIED.md`](APPLIED.md) — current practice

The method for turning a real reaction into diagnosis, alternatives, use, and judgment.

### [`WORKBENCH.md`](WORKBENCH.md) — research synthesis

Longer-lived hypotheses, tensions, experiments, and confidence levels. Useful background; not a to-do list.

## Capture without filing

Leo should not have to stop a thought and decide whether it is “typography,” “interaction,” “industrial design,” “information architecture,” or “game UI.”

When the classification is unclear:

1. put it in the reservoir;
2. keep the source;
3. say what caught the eye;
4. continue living.

Later agents can search, cross-link, and propose groupings. A new category earns existence when several useful things repeatedly want to be found together.

## The trail we want

Over time Tact should contain evidence like:

```text
I saw this thing.
I liked/hated this exact part.
I learned how it worked.
I tried the move somewhere else.
It survived / failed for this reason.
Now I can name the decision.
I keep making this choice across different products.
```

That trail is more valuable than a polished doctrine because it lets future work recover both the judgment and how the judgment was earned.

## What counts as progress

Progress can be any of these:

- one excellent annotated reference;
- one precise diagnosis replacing a vague reaction;
- one screenshot showing a meaningful before/after;
- one study that makes an invisible variable obvious;
- one real interaction improved and used;
- one attractive idea rejected after implementation;
- one recurring choice promoted into the signature;
- one signature claim demoted because another product taught a better answer.

No requirement exists to fill every directory evenly.

## Long-term aim

When Leo starts designing a new app, tool, interface, site, agent workflow, or physical-ish interaction, Tact should be a useful thing to point at and say:

> Read this. Pull the relevant precedents, choices, vocabulary, failures, and unresolved questions. Then help me design *this* thing.

The result should feel informed by a history of looking and making without becoming trapped by that history.
